JWT_NULL_SIG_VULNERABILITY

2026-02-04 3 MIN READ CRITICAL PATCH

A critical vulnerability has been discovered in legacy implementations of JSON Web Token (JWT) libraries. This exploit allows attackers to bypass authentication by setting the algorithm header to "none".

THE_EXPLOIT_VECTOR

JWTs typically consist of three parts: Header, Payload, and Signature. The server verifies the signature to ensure the token hasn't been tampered with. However, many older libraries trust the "alg" (algorithm) field in the header blindly.

If an attacker modifies a captured token to set "alg": "none" and removes the signature, vulnerable servers may accept the token as valid without verifying it. This allows the attacker to impersonate any user, including administrators, by simply modifying the payload.

"Never trust the client. Never trust the header. Validate everything on the server."

REMEDIATION_STEPS

Immediate action is required for all systems using JWT for session management:

  • Audit Dependencies: Check your `package.json` or `go.mod` for outdated JWT libraries.
  • Enforce Algorithm Allowlist: Explicitly configure your verifier to ONLY accept specific algorithms (e.g., HS256, RS256).
  • Reject "None": Ensure your authentication middleware explicitly rejects tokens with "alg": "none".

Security is an ongoing process. Subscribe to CVE feeds for your core dependencies and automate your patch cycle.
